# M2 批次二：UI-16 文件编辑工作区 + UI-17 Git 审查

## 领取理由

依赖已就绪（UI-07/08/09 均已实施）。两任务构成「成果→审查」功能链：共用 main-tabs 标签体系、ContextNav 导航、ProjectWorkbenchContent 渲染分支；UI-17 显式依赖 UI-16。完成后 M2 仅剩 UI-15/19（下一批「资源生命周期」簇）。

现状核心问题（已调查确认）：
- **UI-16**：FileExplorer 嵌入 ContextNav 后仍带独立面板时代外壳（Files 标题行+项目名行+border-left，与导航重复）；编辑器三层「卡片套卡片」（shell→card 描边+大阴影→monaco-pane 24px 圆角）；路径工具行与标签条重复展示文件名；tab 无未保存脏标记；Markdown 预览带「基于 react-markdown 渲染」实现说明（设计 §5.4 明确要求删除）。
- **UI-17**：提交区不显示暂存范围、0 暂存可点提交（后端裸 git commit 失败→原始 stderr 顶部横幅）；错误全部顶部横幅不就地、无重试；parseDiff 埋在组件内不可测；porcelain 重命名 `old -> new` 旧路径被后端丢弃；导航列表行与已打开 diff 无对应高亮；「全部暂存」实际 `add -A` 会波及未跟踪文件（与按钮所在「已修改」区语义不符）。

## 第二部分：UI-17 Git 审查

### 17-A diff 解析抽离（先行，含测试）
- 新建 `src/lib/git-diff.ts`：`parseUnifiedDiff` 从 GitDiffViewer 迁出并增强——结构化产出 `oldPath/newPath/isBinary/isNew/isDeleted/renameFrom/renameTo/similarity`，行号逻辑不变
- `src/lib/git-diff.test.ts`：常规/新文件/删除/二进制/重命名（无 hunk）/行号递进/`\ No newline` 跳过/无 `diff --git` 头兜底，约 10 case

### 17-B 后端重命名旧路径透传（唯一 Rust 改动）
- `GitFileChange` DTO 增加 `origin_path: Option<String>`（前端 `originPath`），`queries.rs` 解析 porcelain `old -> new` 时保留旧路径；抽 `parse_porcelain_line` 纯函数 + cargo 单测
- 无命令签名变化、无 schema 迁移；前端 `GitChanges.tsx` 的 interface 同步

### 17-C GitDiffViewer 改造
- 接新解析器：重命名文件头显示 `old → new`（+ 相似度标注）；二进制显式占位态（不再混入 meta 行）；meta 行噪音过滤；加载/空/错态保留

### 17-D GitChanges 提交区与就地错误
- 提交区头部显示「提交暂存的 N 个文件」（由列表可复算）；N=0 时提交按钮禁用 + 提示「没有已暂存的变更」（空变更不制造成功指标）
- 错误就地：提交/生成错误显示在提交框正下方（含重试按钮；提交文本失败保留——现有行为确认保持）；暂存错误显示在列表区就近位置
- 「全部暂存」改为显式传 `files: 未暂存 tracked 列表`（不再 add -A 波及未跟踪区）
- 移除 `width` prop（同 16-A 模式）

### 17-E 导航列表与 diff 对应
- `ProjectPage` 将 `panels.activeEditorTab` 派生的活动 diff 描述传入 GitChanges/GitHistory
- GitChanges FileRow / GitHistory 提交行：对应 diff 标签为活动主区标签时 `is-active` 高亮
- GitHistory 错误横幅移至操作就近处；行数控制（现 483 行，必要时小拆不超 500）

### 17-F CSS 收敛
- `.ai-git-*` 对齐设计令牌：去装饰性阴影/渐变，保留语义状态色；styles:report 双向通过

### 范围决策（写入任务记录的剩余事项）
- split（并排）diff 不在本轮：任务卡写明「UI-01 确认当前 diff 能力后再估算」，当前为 unified-only，登记待后续
- 历史分页（固定 50 条）不在本轮验收范围
